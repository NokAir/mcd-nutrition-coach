# 麦麦营养点餐助手（MCD Nutrition Coach）

> 按每个人的身体数据和营养目标，搭配适合的麦当劳一餐：多人分别推荐、自动用券、一路到下单确认。

参赛项目：麦当劳程序员节创意开发大赛 · 基于麦当劳 MCP（mcp.mcd.cn）开发

## 解决什么问题

- **「想吃麦当劳，但怕长胖」**：按热量预算推荐，热量/蛋白质/钠三项营养指标直观可见
- **「多人聚餐众口难调」**：每人独立录入身体数据，分别计算目标、分别推荐，再合并成一单
- **「怎么点最划算」**：自动匹配满减券，算出示意到手价

## 功能特性

完整 **8 步交互流程**（单文件 `index.html`，零外部依赖，双击即可运行）：

| 步骤 | 功能 | 说明 |
|---|---|---|
| ① 开始 | 用餐人数 | 1–5+ 人，系统为每个人分别计算营养目标；**1 人时直接进入身体数据表单，不显示「录入伙伴信息」方式选择** |
| ② 身体信息 | 滚轮选择 + BMI 实时计算 | 多人时选择录入方式：手动逐个录入（年龄/性别/身高/体重）/ 跳过按通用预算推荐；**年龄、身高、体重为移动端滚轮选择器**：按住上下滑（带边缘橡皮筋与惯性吸附）、桌面鼠标滚轮、点击某一项、键盘 ↑↓/PageUp/PageDown/Home/End 均可操作，选中即回写数据并实时刷新 BMI |
| ③ 点餐模式 | 随心搭配 / 团购套餐 | 随心搭配＝按 5 类餐型自动组合单品；团购＝按人数/渠道/忌口过滤套餐 |
| ④ 餐型选择 | 5 类餐型方案 | 节俭大学生干饭餐 / 健身能量伙伴餐 / 日常轻松均衡餐 / 轻食控卡体验餐 / 欢乐放纵畅享餐，各有热量区间与蛋白门槛；多人时顶部切换成员、选完自动跳下一位 |
| ⑤ 预算·取餐·口味 | 三大部分合并页 | **预算**（总预算上限）+ **取餐方式**（到店/麦乐送）+ **忌口及偏好口味**（9 类忌口硬过滤 + 6 个口味标签按人独立选择；团购模式为全员统一） |
| ⑥ 选择门店 | 实时定位 + 按渠道过滤 | 麦乐送模式只展示可配送门店；距离按实时定位计算，门店列表随位置自动更新，也可手动刷新 |
| ⑦ 营养推荐 | 每人一份推荐 | 热量/蛋白质/脂肪/碳水/钠/钙逐项展示；不满意可「换饮品/换小食」；预算超支自动降级并在确认弹窗中告知 |
| ⑧ 确认下单 | 订单汇总 + 自动用券 | 满减券自动匹配、示意到手价；演示态下单（完整 Skill 中调用 create-order 返回支付链接） |

其他特性：

- **加载页解释用途**：每个等待步骤都会说明「为什么需要这一步」，例如身体数据只用于估算一餐热量预算、数据不上传
- **按钮音效**：全站按钮有点击反馈音（前进/后退/选中/收银/成功/出错/轻点 7 种场景音 + 小恐龙游戏跳跃/撞击 2 种），Web Audio API 实时合成、零音频文件零依赖；首次手势自动解锁（兼容 iOS Safari 与微信 webview），顶栏提供静音开关（localStorage 记忆），系统「减少动效」偏好下自动静音
- **长加载页留时间玩小游戏**：预算·取餐·口味合并页 → 门店页的加载约 10 秒，进度条匀速推进，小恐龙跑酷游戏约 1.8 秒后出现；其余各步加载约 2–3 秒（含最后提交订单约 2 秒），方便阅读「为什么需要这一步」的小字说明，不弹游戏
- **1 人极简流程**：人数选 1 时跳过「录入伙伴信息」方式选择，直接展示身体数据表单；表单内保留「直接选餐型」入口
- **滚轮选择器录入身体数据**：年龄（5–100 岁）、身高（100–220cm）、体重（30–200kg）改为 iOS 式滚轮，触屏按住上下滑（**索引实时跟随手指**、边缘橡皮筋、松手按速度惯性滑动后吸附最近一格）、桌面鼠标滚轮（滚到头自动放行给页面滚动）、直接点某一项、键盘 ↑↓/PageUp/PageDown/Home/End；换项有轻点音效，`role="spinbutton"` + `aria-valuenow/valuetext` 无障碍语义；内部采用**窗口化渲染**（只画当前 ±3 项共 7 个 DOM 节点，且仅当跨过整数格才重建 DOM，170+ 选项也不掉帧），选中值经隐藏 `input.p-num` 回写，数据结构与校验规则完全不变
- **食物插画**：每个餐品名称前配内嵌 SVG 食物图（巨无霸/麦辣鸡腿堡/板烧/麦香鱼/麦乐鸡/薯条/玉米/苹果派/可乐/零度/雪碧/咖啡/橙汁/麦旋风/圣代等，全菜单覆盖，自绘矢量无版权风险）
- **自绘 SVG 图标系统**：全站 50+ 枚图标（餐型/口味/头像/操作/状态/营养/门店/食物）统一为 24 栅格、1.7px 描边、`currentColor` 继承的自绘矢量图标，由 `ICONS` 字典 + `icon()` 函数生成，零 emoji、零图标库依赖，彻底消除「AI 感」
- **高端视觉设计**：分层柔和阴影、红黄渐变英雄区（带缓慢光泽扫过动画）、渐变营养条、选中卡片弹性反馈动画（ckPop）、加载层径向光晕与漂浮食物图标；顶栏/底栏/卡片/控件统一为 Apple 式模糊玻璃（详见下节）
- **营养推荐引擎**：Mifflin-St Jeor 公式估算 BMR × 1.375（轻度活动）× 35% 作为一餐热量预算；候选组合在餐型达标区间内按「低钠 → 高蛋白 → 低价」排序
- **加载体验**：像素 M 动画 + 进度条；仅「检索门店」一个约 10 秒的长加载页会弹出内置小恐龙跑酷小游戏（Canvas 实现，零外部依赖），其余加载页（2–3 秒）保持清爽、专注读说明
- **异常处理**：换完仍无合适组合时弹出提示；青少年选轻食餐型有温和提醒；加载等待期间点「上一步」不会打断后被强行拽走（导航令牌防护）

## 视觉与动效（Apple 模糊玻璃 + 微交互）

### 玻璃效果怎么做的

三个层次，全部纯 CSS（`backdrop-filter` + 半透明背景 + `inset` 高光 + 噪点），零图片零依赖：

| 层次 | 应用对象 | 参数 |
|---|---|---|
| 一级玻璃 | 卡片、换一批面板、弹窗、加载说明条 | `blur(26px) saturate(180%) brightness(1.02)` + 44% 白釉 + SVG 噪点 + 顶部 1px 内高光 |
| 二级玻璃 | 选项卡、餐型卡、chips、按钮、滚轮 | `blur(16–18px) saturate(170%)` + 34% 白釉 + 亮白描边 + 1px 深色细环（保边界） |
| 导航栏玻璃 | 顶栏、底部操作栏 | `blur(20–24px) saturate(190%)` + 40–44% 白釉，滚动后加深 |

关键前提：**玻璃必须有「背后的彩色光斑」才成立**——`.aurora` 里放了 4 个模糊光斑（品牌黄/红/橙，`blur(64px)`，不透明度 0.9，24–36s 缓慢漂移），光斑只是被 `backdrop-filter` 模糊掉的底色，不参与布局也不抢视线，整体色调仍是红黄 + 米白。**玻璃越透，光斑就要越鲜亮**，否则整面会发灰（这是 v3 调整的核心经验：白釉从 66–80% 降到 28–44%，同时把光斑浓度与 blur 提上去）。

设计取向参考了两个公开实践：

- [kevinbism/liquid-glass-effect](https://github.com/kevinbism/liquid-glass-effect)（MIT）：纯 CSS 玻璃配方——`backdrop-filter` + 半透明描边 + `inset` 内发光 + 边缘高光，本项目的「白釉 + 内高光 + 细环」直接来自这套结构。
- [shuding/liquid-glass](https://github.com/shuding/liquid-glass)（1.2k★，MIT）：用 SVG 位移滤镜做液态折射。本项目**只借用它的"高光沿边缘分布"思路**，没有引入全屏折射——手机端全屏 `feDisplacementMap` 会显著掉帧，且会把小字糊掉；现有效果在 iOS Safari / 微信 webview 上更稳。

### 动效清单（全部可降级）

| 动效 | 触发 | 实现 |
|---|---|---|
| 页面入场 + 子元素错峰上浮 | 每次切页 | `pageIn` + `riseIn`，子元素按 `--i` 依次延迟 42ms |
| 顶栏玻璃加深 | 页面滚动 > 8px | `scroll` + `requestAnimationFrame` 节流，切 `.scrolled` |
| 步数徽标弹一下 | 切页 | `chipBump`（`cubic-bezier(.34,1.56,.64,1)`） |
| 按钮水波纹 | 按下主按钮 | 运行时插入 `.rip`，620ms 后移除 |
| 卡片光标追光 | 桌面精确指针移动 | `pointermove` 写 `--mx/--my`，`radial-gradient` 跟随 |
| 价格数字滚动 | 进入推荐/订单页 | 720ms 三次缓出，`¥` 前缀保留 |
| 营养条生长 | 结果卡渲染 | `@keyframes barGrow{from{width:0}}` |
| 主按钮光泽扫过 | 常驻，4.8s 一次 | `::after` 斜向高光位移 |
| 进度条流光 | 加载/切步 | `#progressBar::after` 循环 |
| 下单成功光环 | 订单成功 | `.ok-ic::after` 扩散环 |
| 悬停抬升 | 桌面 hover | 仅 `(hover:hover) and (pointer:fine)` 生效 |

`prefers-reduced-motion: reduce` 下：所有 CSS 动画时长压到 0.01ms，JS 侧 `Motion` 模块直接跳过水波纹/追光/数字滚动，只保留静态玻璃；音效同时自动静音。


## 安装与运行

### 1. 运行 UI 原型（无需构建、无外部依赖）

方式一：直接用浏览器打开 `index.html`

方式二：本地起个静态服务

```bash
cd mcd-nutrition-assistant
python3 -m http.server 8080
# 浏览器访问 http://localhost:8080
```

### 2. 配置麦当劳 MCP（接入真实数据）

1. 打开 [open.mcd.cn/mcp](https://open.mcd.cn/mcp)，手机号登录 → 右上角「控制台」→ 激活并申请 MCP Token
2. 参考 `mcp-config.example.json`，在 MCP 客户端（推荐 WorkBuddy：连接器 → 自定义连接器 → 配置 MCP）中填入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer ${MCD_MCP_TOKEN}" }
    }
  }
}
```

3. 把 `${MCD_MCP_TOKEN}` 替换为你自己的 Token，保存并启用连接器

> ⚠️ Token 只存放在本机客户端配置或环境变量中，**切勿提交到公开仓库**或贴到公开页面。

## 使用示例

配置好 MCP 后，在对话中直接描述需求即可，例如：

> 「我在天津蓟州，3 个人一起吃麦当劳，要麦乐送。我 28 岁男 75kg 想控制热量，朋友不限。帮我每人推荐一份，总价控制在 120 以内。」

Skill 会依次执行：识别当前时段 → 查询可配送门店 → 让你选店 → 拉取当次菜单 → 按每人餐型与热量预算筛选组合 → 匹配优惠券 → 核价 → **你明确确认后**才创建订单。

UI 原型（`index.html`）内置了全流程交互演示，不依赖 Token 即可完整体验。

## 目标用户

- **减脂 / 健身 / 控钠人群**：吃麦当劳但需要控制热量、蛋白质、钠摄入
- **多人聚餐场景**：需要快速协调多人不同饮食目标
- **价格敏感用户**：希望自动用券拿到更低到手价
- **学生党 / 性价比人群**：预算敏感，需要在预算内吃饱吃好

## 数据说明与免责声明

- `index.html` 中的餐品营养、价格、门店、优惠券均为**演示用模拟值**（字段结构与麦当劳 MCP 返回对齐），真实数据以麦当劳 MCP 实时返回为准
- **定位仅用于计算你与门店的距离**：使用浏览器 `navigator.geolocation`，位置信息不存储、不上传；拒绝授权时回退到演示距离
- **团购套餐数据为演示用途**：麦当劳官方 MCP 工具清单中暂无团购套餐查询工具，团购信息在真实场景中来自美团/抖音等渠道；`GROUP_DEALS` 仅用于演示交互链路
- 热量预算为公式估算值，仅供参考，不构成医疗或营养建议
- `create-order` 为真实写操作，完整 Skill 中仅在用户明确确认后调用
- 参赛项目为麦当劳程序员节创意开发大赛参赛作品，由参赛者独立开发，非麦当劳官方产品
